## What this is

WORLD FILM — a **static marketing website** (hand-written HTML + CSS, no framework, no backend) for a Thai window-tint / solar-film installation business. All content is Thai (`<html lang="th">`). There is **no build step, no `package.json`, no tests, and no linter**. **Node.js is not installed** (no `npm`/`npx`) and neither is `gh`. **Python 3.11.9 is** — call it as `python` or `py` (`python3` is a Microsoft Store stub, never use it) — but with **no Pillow**, so image resizing stays on PowerShell `System.Drawing`. Its stdout is cp1252 in this shell, so **run it as `python -X utf8`** whenever a script prints Thai (`print('ไทย')` otherwise dies with `UnicodeEncodeError: 'charmap'`); reading/writing files is fine as long as you pass `encoding='utf-8'` explicitly. Earlier revisions of this file claimed Python was absent; that was wrong (corrected 2026-09-16).

## Running / previewing

- Quickest look: open `index.html` in a browser directly.
- For anything needing HTTP (the Chrome-automation extension blocks `file://`): the simplest server is Python's — `python -m http.server 8753 --bind 127.0.0.1` from the repo root (Bash tool, `run_in_background`; verified 2026-09-16: `text/html` / `text/css` types are right and the pages' `<meta charset="UTF-8">` carries the Thai). Stop it with `taskkill //F //IM python.exe` from Bash. Pages live at `/index.html`, `/works.html`, `/about.html`, `/contact.html`, `/products/*.html`. The older PowerShell `System.Net.HttpListener` recipe below still works as a fallback (adjust `$root`/`$prefix`):
  ```powershell
  $root='C:\Claude\ProjectWorldFilm'; $prefix='http://localhost:8753/'
  $l=[System.Net.HttpListener]::new(); $l.Prefixes.Add($prefix); $l.Start()
  while($l.IsListening){ $c=$l.GetContext()
    $rel=[Uri]::UnescapeDataString($c.Request.Url.AbsolutePath.TrimStart('/')); if(!$rel){$rel='index.html'}
    $p=Join-Path $root $rel
    if(Test-Path $p -PathType Leaf){
      $ext=[IO.Path]::GetExtension($p)
      $c.Response.ContentType=@{'.html'='text/html; charset=utf-8';'.css'='text/css; charset=utf-8';'.png'='image/png';'.jpg'='image/jpeg'}[$ext]
      $b=[IO.File]::ReadAllBytes($p); $c.Response.OutputStream.Write($b,0,$b.Length)
    } else { $c.Response.StatusCode=404 }
    $c.Response.Close() }
  ```
- **Neither server sends `Cache-Control`** (Python's adds only `Last-Modified`), so Chrome will happily re-show the pre-edit page and make a correct fix look broken. Always cache-bust when re-checking an edit: navigate to `http://localhost:<port>/index.html?v=2` (bump the number each reload) rather than reloading the bare URL.
- **Stopping the server:** the listening socket is owned by http.sys (System / PID 4), not the script — kill the `powershell.exe` whose CommandLine contains the script name, never the port owner.
- **Testing mobile widths in Chrome automation:** `resize_window` reports success but the OS ignores it on this machine. Instead inject an `<iframe src="index.html" style="width:430px;height:932px">` via `javascript_tool` and inspect/click inside `contentDocument` (same-origin on localhost). **The automation tab reports `document.hidden === true`** (checked 2026-09-16), so anything that needs a visible document is inert there: `scroll-behavior: smooth` scrolls never move (`scrollTo`/`scrollIntoView` silently stay put — pass `{behavior:'instant'}`), the `.reveal` IntersectionObserver doesn't fire on programmatic scrolls (use the `computer` tool's mouse-wheel `scroll`, which does trigger it), and a screenshot taken right after a JS scroll can come back blank — nudge with one wheel tick first. None of that is a site bug.
- Many sections start hidden (`.reveal` = opacity 0 until scrolled into view via IntersectionObserver). After navigating, scroll so they animate in before screenshotting, or the page looks blank. **This applies to the 4 root pages only** — see the `.reveal` note under Architecture; `products/*` pages render everything immediately.

## Verifying a sitewide change

There is no linter or test suite, so the check that a shared-chrome / duplicated-block edit actually landed on **every** copy is a counting grep. Run one after any sweep — a page that silently didn't match shows up as a missing row or a wrong count:

```bash
# featurebar: the strongest single check — proves wording, not just presence.
# All 4 canonical pairs must come back at exactly 13 each (contact.html renders its own markup = the 14th page).
grep -rho '><b>[^<]*</b><span>[^<]*</span>' --include=*.html . | sort | uniq -c | sort -rn
grep -rl 'getComputedStyle(burger)' --include=*.html . | wc -l # expect 17 (every page)
grep -rc '095-229-2086' --include=*.html .    | grep -v ':0'   # 5/page (6 on contact, 4 on the 3 short brand pages)
grep -rho 'data-th="[^"]*"' --include=*.html . | sort | uniq -c # expect all 5 nav labels × 17
grep -rc 'class="gslide' --include=*.html . | grep -v ':0' # exactly 5 files: works.html 82 (15 real cards × 4–6) · uvguard 30 · ceramic 23 · nanoceramic 23 · crystalize 12 — the other 6 spec pages have no gallery at all since 2026-09-17
grep -rho 'assets/logo-white.png' --include=*.html . | wc -l   # expect 34 = 17 pages × (header + footer)
grep -rho 'images.unsplash.com' --include=*.html . | wc -l     # expect 9 — index 6 (hero slide 1 + 5 .fslide) · about 2 · works 1, all decorative
grep -rc 'class="workcard' --include=*.html . | grep -v ':0'    # expect exactly 5 files: works 15 · uvguard 6 · ceramic 4 · nanoceramic 4 · crystalize 2 — a 6th file means a stock card came back
find assets/works -name '*.jpg' | wc -l                        # expect 82 across 15 project folders
```
**All of the above were re-verified 2026-09-17 (and 2026-09-16 / 2026-07-30 before that) and every count matched** — if one comes back different, something drifted since then, so treat the mismatch as the finding rather than re-deriving the whole table. One row that is *not* drift: the featurebar grep also returns `1 ><b>1000+</b><span>โครงการที่ส่งมอบ</span>` — that is `works.html`'s hero `.mini` stat (see Content conventions), which happens to share the markup shape.

Same idea for any duplicated block: grep the **text**, not the class, and check the count is uniform. A page the editor re-wrapped (see the auto-format note above) still matches a short text fragment when a whole-tag `Edit` would have missed it.

**The `><b>` featurebar grep silently skips `contact.html`.** Its 4 items sit in `.vprop`/`.m` markup whose `<b>` starts a fresh line, so the glued `><b>` pattern can't match — which is exactly why that check tops out at 13, not 14. For a **wording** sweep (as opposed to a structural one) always follow up with a bare text count so the 14th page can't be left behind:
```bash
grep -rl 'ประเมินพื้นที่หน้างานฟรี' --include=*.html . | wc -l   # expect 14, not 13
```
Watch for prose hits when text-counting a word that also appears in ordinary copy: `contact.html` says `ประเมินหน้างานฟรี` in a normal sentence (~line 439) independently of its featurebar item, so grepping the bare word `ประเมิน` returns one more hit than there are featurebar copies. Count the **full item label**, not the bare word.

## Architecture — the big picture

**Every page is a standalone, fully self-contained HTML file. There is no templating or shared include.** The floating capsule header (sticky navy pill nav + dropdown + CTA copy-phone pill) and footer are **copy-pasted into every `.html` file** (there is **no top utility bar** — it was removed when the capsule header landed, and **no floating LINE/call FAB** — removed 2026-07-30). Any change to shared chrome (nav items, phone number, footer links) must be repeated across **all** pages. For sitewide text/link edits, prefer a scripted pass (`sed`), but match only the **ASCII** portion of the string — matching Thai bytes via PowerShell/sed is fragile.

**The user's editor auto-formats HTML on save (Prettier-style)**, so identical shared chrome can be line-wrapped differently per file: long tags get split with the closing `>` pushed to the next line (`<a href="…"` / `><span class="bl"` / `>Finnix</a` / `>`). Consequences: an `Edit` old_string that matched one page may not match the next; anchor sitewide `sed`/`Edit` passes on short unique fragments (an `href` value, a phone number) instead of whole tags; and expect formatting-only reflow noise in `git diff` after the user has files open. `git diff`'s `LF will be replaced by CRLF` warnings are autocrlf chatter — ignore them.

**CSS lives in two places and is partly duplicated:**
- `index.html` carries its **entire stylesheet inline** in one `<style>` block, including design tokens and shared-chrome styles.
- `products/product.css` is the **shared stylesheet**, linked by every non-homepage page — `products/*.html` link `product.css`; root pages `contact.html` and `works.html` link `products/product.css` and add their own page-specific inline `<style>`.
- **Dead CSS is kept on purpose, and it can bite.** Two rule sets in `product.css` have no markup using them anywhere: `.sample-note` (~line 970 — the yellow "sample data" banner) and `.spectable` (7 base rules ~line 466 + 2 in the `≤768` block). Both are retained because the markup is expected back once the owner supplies real specs — but it means **pasting a `<div class="sample-note">` or `<div class="spectable">` silently revives a whole styled component**, so don't, unless asked. Already-deleted-for-good, don't recreate: `.swatch--img`, `.phl`/`.hi`, `.fab`. Going the other way, `works.html`'s `.work-hero .mini` sat dead for weeks, came back 2026-07-28, was cut 2026-07-30 and restored the same day — so absent markup really doesn't mean the rules are safe to delete. Same for `about.html`'s `.about-stats`. Each case has its own bullet further down with the history.
