# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

WORLD FILM — a **static marketing website** (hand-written HTML + CSS, no framework, no backend) for a Thai window-tint / solar-film installation business. All content is Thai (`<html lang="th">`). There is **no build step, no `package.json`, no tests, and no linter**. Node.js and Python are **not installed** on the dev machine — do not reach for `npm`, `npx`, or `python -m http.server`.

## Running / previewing

- Quickest look: open `index.html` in a browser directly.
- For anything needing HTTP (the Chrome-automation extension blocks `file://`): serve with a PowerShell `System.Net.HttpListener` bound to `http://localhost:<port>/` (run with `run_in_background`). Pages live at `/index.html`, `/works.html`, `/about.html`, `/contact.html`, `/products/*.html`. Concrete server (adjust `$root`/`$prefix`):
  ```powershell
  $root='C:\Claude\ProjectWorldFilm'; $prefix='http://localhost:8753/'
  $l=[System.Net.HttpListener]::new(); $l.Prefixes.Add($prefix); $l.Start()
  while($l.IsListening){ $c=$l.GetContext()
    $rel=[Uri]::UnescapeDataString($c.Request.Url.AbsolutePath.TrimStart('/')); if(!$rel){$rel='index.html'}
    $p=Join-Path $root $rel
    if(Test-Path $p -PathType Leaf){
      $ext=[IO.Path]::GetExtension($p)
      $c.Response.ContentType=@{'.html'='text/html; charset=utf-8';'.css'='text/css; charset=utf-8';'.png'='image/png';'.jpg'='image/jpeg'}[$ext]
      $b=[IO.File]::ReadAllBytes($p); $c.Response.OutputStream.Write($b,0,$b.Length)
    } else { $c.Response.StatusCode=404 }
    $c.Response.Close() }
  ```
- **The listener above sends no `Cache-Control`**, so Chrome will happily re-show the pre-edit page and make a correct fix look broken. Always cache-bust when re-checking an edit: navigate to `http://localhost:<port>/index.html?v=2` (bump the number each reload) rather than reloading the bare URL.
- **Stopping the server:** the listening socket is owned by http.sys (System / PID 4), not the script — kill the `powershell.exe` whose CommandLine contains the script name, never the port owner.
- **Testing mobile widths in Chrome automation:** `resize_window` reports success but the OS ignores it on this machine. Instead inject an `<iframe src="index.html" style="width:430px;height:932px">` via `javascript_tool` and inspect/click inside `contentDocument` (same-origin on localhost).
- Many sections start hidden (`.reveal` = opacity 0 until scrolled into view via IntersectionObserver). After navigating, scroll so they animate in before screenshotting, or the page looks blank. **This applies to the 4 root pages only** — see the `.reveal` note under Architecture; `products/*` pages render everything immediately.

## Verifying a sitewide change

There is no linter or test suite, so the check that a shared-chrome / duplicated-block edit actually landed on **every** copy is a counting grep. Run one after any sweep — a page that silently didn't match shows up as a missing row or a wrong count:

```bash
# featurebar: the strongest single check — proves wording, not just presence.
# All 4 canonical pairs must come back at exactly 13 each (contact.html renders its own markup = the 14th page).
grep -rho '><b>[^<]*</b><span>[^<]*</span>' --include=*.html . | sort | uniq -c | sort -rn
grep -rl 'getComputedStyle(burger)' --include=*.html . | wc -l # expect 17 (every page)
grep -rc '095-229-2086' --include=*.html .    | grep -v ':0'   # 5/page (6 on contact, 4 on the 3 short brand pages)
grep -rho 'data-th="[^"]*"' --include=*.html . | sort | uniq -c # expect all 5 nav labels × 17
grep -rc 'class="gslide' --include=*.html . | grep -v ':0' # works.html 30 (6 cards×5); each spec page 15 (3×5)
grep -rho 'assets/logo-white.png' --include=*.html . | wc -l   # expect 34 = 17 pages × (header + footer)
```
**All of the above were re-verified 2026-07-30 and every count matched** — if one comes back different, something drifted since then, so treat the mismatch as the finding rather than re-deriving the whole table.

Same idea for any duplicated block: grep the **text**, not the class, and check the count is uniform. A page the editor re-wrapped (see the auto-format note above) still matches a short text fragment when a whole-tag `Edit` would have missed it.

**The `><b>` featurebar grep silently skips `contact.html`.** Its 4 items sit in `.vprop`/`.m` markup whose `<b>` starts a fresh line, so the glued `><b>` pattern can't match — which is exactly why that check tops out at 13, not 14. For a **wording** sweep (as opposed to a structural one) always follow up with a bare text count so the 14th page can't be left behind:
```bash
grep -rl 'ประเมินพื้นที่หน้างานฟรี' --include=*.html . | wc -l   # expect 14, not 13
```
Watch for prose hits when text-counting a word that also appears in ordinary copy: `contact.html` says `ประเมินหน้างานฟรี` in a normal sentence (~line 455) independently of its featurebar item, so grepping the bare word `ประเมิน` returns one more hit than there are featurebar copies. Count the **full item label**, not the bare word.

**Page-count invariants** (recheck these before trusting any "all N pages" phrasing below — the counts grew as pages were added): **17 HTML pages** total = 4 root (`index` · `about` · `works` · `contact`) + 4 `brand-*` + 9 `model-*`. Of those, **10 are "spec pages"** (the 9 `model-*` + `brand-regionfilm`), **14 carry the contact section** (17 − the 3 short brand pages), and shared chrome (capsule header, Products accordion, smart-hide nav, `#copyPill`, footer) is on all **17**. The floating LINE/call buttons (FAB) used to be part of that list — **removed sitewide 2026-07-30**, see the FAB bullet under Content conventions.

## Architecture — the big picture

**Every page is a standalone, fully self-contained HTML file. There is no templating or shared include.** The floating capsule header (sticky navy pill nav + dropdown + CTA copy-phone pill) and footer are **copy-pasted into every `.html` file** (there is **no top utility bar** — it was removed when the capsule header landed, and **no floating LINE/call FAB** — removed 2026-07-30). Any change to shared chrome (nav items, phone number, footer links) must be repeated across **all** pages. For sitewide text/link edits, prefer a scripted pass (`sed`), but match only the **ASCII** portion of the string — matching Thai bytes via PowerShell/sed is fragile.

**The user's editor auto-formats HTML on save (Prettier-style)**, so identical shared chrome can be line-wrapped differently per file: long tags get split with the closing `>` pushed to the next line (`<a href="…"` / `><span class="bl"` / `>Finnix</a` / `>`). Consequences: an `Edit` old_string that matched one page may not match the next; anchor sitewide `sed`/`Edit` passes on short unique fragments (an `href` value, a phone number) instead of whole tags; and expect formatting-only reflow noise in `git diff` after the user has files open. `git diff`'s `LF will be replaced by CRLF` warnings are autocrlf chatter — ignore them.

**CSS lives in two places and is partly duplicated:**
- `index.html` carries its **entire stylesheet inline** in one `<style>` block, including design tokens and shared-chrome styles.
- `products/product.css` is the **shared stylesheet**, linked by every non-homepage page — `products/*.html` link `product.css`; root pages `contact.html` and `works.html` link `products/product.css` and add their own page-specific inline `<style>`.
- **Dead CSS is kept on purpose, and it can bite.** Two rule sets in `product.css` have no markup using them anywhere: `.sample-note` (~line 989 — the yellow "sample data" banner) and `.spectable` (7 base rules ~line 454 + 2 in the `≤768` block). Both are retained because the markup is expected back once the owner supplies real specs — but it means **pasting a `<div class="sample-note">` or `<div class="spectable">` silently revives a whole styled component**, so don't, unless asked. Already-deleted-for-good, don't recreate: `.swatch--img`, `.phl`/`.hi`, `.fab`. Going the other way, `works.html`'s `.work-hero .mini` sat dead for weeks and is live again since 2026-07-28 — so absent markup doesn't mean the rules are safe to delete either. Each case has its own bullet further down with the history.
- The `:root` tokens and shared-component classes (`.header` `.nav` `.menu` `.submenu` `.pill` `.nav-call` `.burger` `.footer` `.btn` `.eyebrow` `.section` `.wrap`) are **defined twice** — once inline in `index.html`, once in `product.css`. Keep both in sync when touching shared UI. When moving a homepage component to another page, its classes may exist **only** in the inline block — copy the needed CSS into `product.css` first (this is how `.featurebar` / `.contact-cards` / `.ccard` got there).

**Design tokens** (in both stylesheets): navy `--ink:#14223d` + gold `--gold:#c0973f` / `--gold-bright`, warm paper backgrounds. Fonts: **IBM Plex Sans Thai only** — Trirong and Cormorant Garamond were removed sitewide 2026-07-18 (user wants one uniform font); the `.h-thai` / `.serif` class names still exist in markup and CSS but now resolve to IBM Plex Sans Thai, and the Google Fonts links load just the one family. Sections alternate `.section` (paper) / `.section--tint` (light) / `.ctaband` (navy).

**Per-page JS** is a small inline `<script>`, duplicated per page: header shadow on scroll, mobile burger toggle, the mobile Products-accordion toggle (added 2026-07-21, see capsule header below), and the CTA pill copy handler (`#copyPill` — fire-and-forget `navigator.clipboard.writeText`, **never `await` it**: it hangs when the document isn't focused; shows ✓ "คัดลอกเบอร์แล้ว" for 2s). Lazy background images (`[data-img]` attributes loaded into `background-image`, degrading to navy if the image fails) exist where there are photo tiles: `index.html` (`.tile` / `.hero-slides .slide` / `.fslide`), `works.html` (`.thumb`, and — since 2026-07-20 — nested `.gslide` layers, see below), and — since the works-preview section landed 2026-07-20 — every model page + `brand-regionfilm.html` (`.workcard .gslide` layers since 2026-07-22; the old `.thumb[data-img]` loader on those 10 pages was replaced by the per-card gallery init, which both loads the slides and wires the dots).

**Almost every photo on the site is a remote Unsplash URL — only the logos and the 2 hero JPEGs are local.** `assets/` holds just logos/icons (`logo-white.png`, `line.png`, `facebook.png`, `brands/*`, `models/*`) plus `hero/hero-family-pets.jpg` + `hero-install-team.jpg`. Everything else — every `.tile`, `.fslide`, `.thumb`, `.gslide`, `.sc-view` — is `https://images.unsplash.com/photo-…?…&w=NNN`, and it is **9 distinct photo IDs reused ~194 times**: 11 in `index.html`, 31 in `works.html`, 2 in `about.html`, 15 on each of the 10 spec pages. Three consequences: **(a)** previewing with no network (or a blocked host) shows the navy `data-img` fallback on every tile — that looks broken but isn't, so don't "fix" it; **(b)** the site is one third-party outage away from having no photos, worth mentioning if the owner asks about hosting; **(c)** a "use our real photos" request is a **per-photo-ID sweep, not a per-page one** — swapping one ID with `sed` hits all its copies at once, and the counts above are the check that it landed. Same `assets/PIC/` → web-ready-JPEG workflow as the hero (see the `assets/PIC/` bullet) for whatever the owner supplies.

**`.reveal` scroll-in animation is root-pages-only — on `products/*` it is inert dead markup.** The `.reveal` CSS rule and the IntersectionObserver that clears it live **only** in the 4 root pages' own inline `<style>`/`<script>` (`index` · `works` · `about` · `contact`). `product.css` has **no `.reveal` rule** and no product page has an IntersectionObserver — yet each of the 9 `model-*.html` pages still carries 3 elements with `class="… reveal"` left over from the page generator. They render normally (no rule = no `opacity:0`), so this is harmless, but: adding `class="reveal"` to a product page animates nothing, and if you ever copy the `.reveal` **CSS** into `product.css` without also copying the observer, those 27 existing elements go invisible sitewide. Move both or neither.

**Responsive.** Desktop-first; mobile behavior lives entirely in `@media` blocks so the desktop layout is the base. The standardized breakpoints are **768px** (primary mobile: hamburger appears, touch targets forced to `min-height:44px`) and **480px** (small-phone font/spacing reductions), with a **980px** tablet tier for some grids. When adjusting mobile, keep every change inside a `≤768`/`≤480` media query so widths above 768px stay untouched — and mirror the edit in both `index.html` inline CSS and `product.css`. **Mobile keeps rows/columns close to the desktop layout (user direction, 2026-07-21)** — not everything stacks to one column: `.benefits` stays 2×2, `.featurebar`'s grid and `.footer .top` stay 2-column down to the smallest widths (their old 1-column overrides were deliberately deleted — don't re-add them), and `.brandlogos` is a single row of 4 even at ≤480px.
